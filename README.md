# Daily Check-in · 日常 Daykeep

一个面向个人长期使用的日常管理与监督打卡 Web 应用。用一处清爽的空间，记录任务、消费、学习、体重和饮食，了解每天的状态与长期变化。

第一版无需注册或登录，没有后端和数据库。记录保存在当前设备、当前浏览器的网站本地存储中；正常关闭网页后仍然保留。

## 开始使用

需要 Node.js 22.12 及以上版本，推荐 Node.js 24，以及随 Node.js 安装的 npm。在项目目录打开终端，依次运行：

```bash
npm install
npm run dev
```

本地开发时，打开终端中显示的网址，通常为 `http://localhost:5173`。当前云环境的项目目录是 `/workspace/daily-checkin`。开发服务器默认监听 `0.0.0.0`；应用也可构建后部署到静态网站托管服务。

第一次打开时没有预填记录。可以直接开始使用，也可以在「设置 → 体验示例数据」中载入一组可选的 7 天示例。载入示例会替换现有记录与设置，并需要确认；已有真实数据时请先导出备份。

建议先在「设置」中填写昵称、每日学习目标和每日热量记录参考，在「体重管理」中设置目标体重，再从首页开始记录今天的生活。

## 可以做什么

| 页面     | 功能                                                                                                |
| -------- | --------------------------------------------------------------------------------------------------- |
| 首页     | 查看日期、今日任务完成率、消费、学习时间、体重、估算热量和连续打卡天数；查看各类记录与最近 7 天趋势 |
| 每日打卡 | 新增、编辑、删除任务，选择所属日期，标记完成或未完成，查看历史与每日完成率                          |
| 消费管理 | 按金额、类别、日期、时间和备注记账；查看当日与所选月份总额、分类占比、7 天趋势与消费明细            |
| 学习记录 | 按内容、主题、时长、日期和备注记录学习；查看当日、所选周和所选月份时长、目标进度和 7 天趋势         |
| 体重管理 | 记录每日体重、设置目标，查看变化曲线、与目标的距离和具备足够记录时的趋势估算                        |
| 饮食记录 | 按早餐、午餐、晚餐和加餐记录食物、数量、估算热量与备注，统计当日热量，并提供下一餐的简单生活建议    |
| 数据统计 | 集中查看打卡完成率、消费、学习时间、体重和每日热量的图表                                            |
| 设置     | 修改个人偏好，导出或导入 JSON 备份，载入可选示例，清空全部记录                                      |

消费类别包括餐饮、交通、购物、娱乐、学习和其他。消费、学习与饮食页面可通过日期选择器及前后一天按钮回看历史记录。编辑记录时也可以更改日期。

连续打卡按「当天有任务且全部完成」统计；当天尚未全部完成时，从昨天向前计算连续天数。没有任务的日期不会算作已完成打卡。

## 数据位置与备份

全部记录和个人设置保存在浏览器 `LocalStorage` 中，主存储键为 `daykeep:data:v1`。应用的数据访问、校验和汇总逻辑集中在 `src/lib/data.ts`，数据结构在 `src/lib/types.ts`，便于以后接入数据库或云端同步。

请定期在「设置 → 导出备份」中下载 JSON 文件。备份包含所有记录和个人设置；文件名类似 `daykeep-backup-2026-10-16.json`。请妥善保管文件，其中包含个人生活数据。

恢复时，在「设置 → 导入备份」选择本应用导出的 JSON 文件，并确认恢复。导入会校验数据格式，且会**替换当前全部记录与设置**，不会自动合并；恢复前建议先导出现有数据。单个导入文件限制为 20 MB（包含 JSON 格式化空格），实际保存仍受浏览器存储配额限制。

需要了解的限制：

- 清理浏览器网站数据、使用隐私模式、更换浏览器或设备，可能使已有记录无法访问或丢失。
- 不同网址、域名或端口拥有独立存储。例如 `localhost:5173` 的记录不会自动出现在 `localhost:4173` 中。更换访问地址前可以先导出备份。
- 当前版本没有云端同步、账号恢复或自动远程备份。跨设备迁移需要手动导出和导入 JSON 文件。
- 浏览器本地存储有容量限制。若页面提示保存失败，请先导出备份并检查浏览器存储权限或空间。
- 「清空数据」会删除记录并重置设置；未经备份的数据无法通过本应用恢复。

## 体重与饮食提示的范围

体重预测使用最近一次称重前 30 天内记录的线性趋势，只是个人生活管理参考，不是医学建议。至少需要 3 次称重，且记录跨度达到 7 天；最新记录超过 30 天、数据不足、趋势较稳定、变化方向与目标不同，或预测不适合展示时，不给出到达日期。实际体重会自然波动，未来变化不一定延续历史趋势。

饮食热量由使用者自行估算，不能视为精确摄入量。下一餐建议根据已记录饮食、热量参考和体重目标提供普通生活提示，不进行医学诊断，也不会替代个体化营养指导。是否完整记录同样会影响统计和建议。

## 构建与预览

```bash
npm run build
npm run preview
```

`build` 先运行 TypeScript 检查，再生成 `dist/` 静态文件；`preview` 用于本地预览构建结果，通常地址为 `http://localhost:4173`。`dist/` 可以部署到支持静态网站的托管服务，应用本身无需后端服务。

仓库包含 `package-lock.json`。后续需要严格按锁文件重现依赖时，可使用 `npm ci` 安装。

## 运行测试

运行数据逻辑等单元测试：

```bash
npm test
```

端到端交互测试使用 Playwright。在当前云环境中已提供系统 Chromium，配置会自动检测并使用它，直接运行：

```bash
npm run test:e2e
```

在自己的电脑上，如果没有系统 Chromium，先安装 Playwright 配套浏览器，再运行同一命令：

```bash
npx playwright install chromium
npm run test:e2e
```

浏览器安装需要网络连接。若系统缺少 Chromium 所需的系统库，按 Playwright 的报错提示安装对应依赖后重试。测试命令的实际执行结果以终端输出为准。

## 技术与项目结构

使用 React、TypeScript、Vite 和 Tailwind CSS；图表由 Recharts 绘制，图标来自 Lucide。界面以电脑端为主，同时适配手机端；业务页面、公共 UI 和数据逻辑分开组织。

```text
daily-checkin/
├── public/                 # 网站静态资源
├── src/
│   ├── components/
│   │   └── ui.tsx          # 卡片、表单、弹窗、确认框及图表提示
│   ├── lib/
│   │   ├── types.ts        # 记录类型与页面接口
│   │   ├── data.ts         # LocalStorage、数据校验、统计、预测与建议
│   │   └── data.test.ts    # 数据逻辑单元测试
│   ├── pages/
│   │   ├── Dashboard.tsx   # 今日首页
│   │   ├── Tasks.tsx       # 每日打卡
│   │   ├── Expenses.tsx    # 消费管理
│   │   ├── Study.tsx       # 学习记录
│   │   ├── Weight.tsx      # 体重管理
│   │   ├── Diet.tsx        # 饮食记录
│   │   ├── Analytics.tsx   # 数据统计
│   │   └── Settings.tsx    # 个人设置与数据备份
│   ├── App.tsx             # 应用导航、页面切换与数据状态
│   ├── index.css           # 主题、组件样式与响应式布局
│   └── main.tsx            # 应用入口
├── package.json            # 依赖与运行命令
├── package-lock.json       # 锁定依赖版本
└── vite.config.ts          # 开发与构建配置
```

后续接入云端时，可以在保留页面数据接口的基础上替换数据存取层，再增加用户身份与同步机制。当前版本不需要任何 API Key 或环境变量即可运行。
